# CR-009：ESP32-S3 网络日志源与采集契约

- **提出方：** A0 架构与协议（基于 A7 缺口记录）
- **提出日期：** 2026-10-22
- **状态：** **OPEN — 当前没有网络日志契约；网络日志能力未定义、未支持**
- **关联：** `docs/acceptance/network-log-source-gap-2026-10-22.md`、`docs/implementation/interfaces.md`、`firmware/components/desk_sdk_bridge/src/desk_sdk_bridge.c`、`tools/verification/capture_esp32s3_logs.py`
- **影响模块：** A0（契约裁决）；若批准网络来源，由 A1 负责固件日志源、A7 负责采集与验收适配

## 1. A0 当前裁决

仓库中没有定义或实现 ESP32-S3 网络日志订阅、日志数据帧、日志 sink 或日志服务端点的契约。现有 TCP 37020 是控制/响应桥，UDP 37021 是配对发现；不能将控制响应、业务事件或配对数据解释为日志，也不能在这些通道上自行增加日志语义。

当前可支持的 ESP32-S3 日志采集能力冻结为 **UART-only**：`tools/verification/capture_esp32s3_logs.py` 从串口被动读取，按行解析，可将脱敏事件实时写为 JSONL；`--no-raw` 不持久化原始字节。工具测试只证明 L2 行为；此前 UART 现场采集属于有限的 L3 观测，不证明网络日志能力。

在本 CR 后续裁决并有实现、测试前，网络日志采集必须报告为 **未定义/不支持**。不得连接 37020/37021 试探日志接口，不得通过命令桥轮询或订阅来冒充日志源，也不得声称已有实时网络日志能力。

## 2. 现有证据与范围边界

1. `docs/implementation/interfaces.md` §5 的 L-02/L-03 将 TCP 37020 定义为 `RequestEnvelope` / `ResponseEnvelope` 控制桥；L-09 定义官方 SDK 的配对发现和数据通道。该目录没有日志链路。
2. `desk_sdk_bridge.c` 实现配对、命令、事件和媒体通道；检索未发现网络日志订阅或 ESP 日志转发接口。已发现的应用事件并非任意固件日志流。
3. `capture_esp32s3_logs.py` 的数据源是 UART；其 `--capture` 是被动读取。A7 缺口记录给出当前工具与测试边界。
4. 本 CR 只确立“无现存网络日志契约”和当前 UART-only 能力边界；不选定网络 transport、端口、wire schema、固件组件或部署配置。

## 3. 若纳入范围，A0 必须先裁决的最小契约字段

任何网络采集实现派发前，A0 必须通过后续明确裁决补齐下列字段。以下是决策清单，不是新协议或已批准 wire 设计：

| 决策域 | 必须明确的内容 |
| --- | --- |
| 权威数据源 | ESP-IDF 日志、应用结构化诊断事件或指定 logger 的唯一来源；日志级别/类别、时间戳来源、丢失与重复语义，以及哪些敏感字段在设备端禁止输出 |
| 连接方向与发现 | 谁主动连接谁、发现机制、绑定到设备身份的方法、与现有控制桥隔离方式；不得默认复用 37020/37021 |
| 版本与帧 | 独立协议/Schema 版本、消息类型、长度/边界、编码、序列/时间语义、完整性校验、未知版本与未知字段行为；需有可验证正例和负例 fixture |
| 鉴权与脱敏 | 配对/设备身份与授权模型、凭据生命周期、传输保护；设备端和采集端的字段级脱敏规则、拒绝或丢弃条件、原始 payload 默认不落盘 |
| 背压与重连 | 有界缓冲与溢出策略、丢弃计数/序列缺口、订阅节流、断线重试和恢复游标语义；严禁无界内存增长或断线后无限重放 |
| 只读保证 | 采集协议不得承载控制副作用；定义订阅/取消订阅允许操作及审计，验证客户端不会发送业务命令或改变设备状态 |
| 兼容性与部署 | 支持的固件版本/能力协商、无网络日志能力的旧固件退化行为、配置开关、与 UART 采集并存规则及升级/回退兼容策略 |

只有 A0 发布具体且可测试的契约后，A1 才能实现固件侧来源，A7 才能实现网络采集器并运行协议测试与真机验证。若最终决定不纳入范围，应在后续裁决中关闭此 CR，并维持 UART-only。

## 4. 验收门槛

- **契约阶段（A0）：** 上表决策全部有明确值，更新相应公共接口/Schema 与兼容性说明；定义版本化 fixtures 和负例；不以此宣称设备实现完成。
- **实现阶段（A1/A7）：** 不影响既有命令桥；鉴权失败、畸形帧、未支持版本、脱敏、缓冲溢出、断线/恢复均有测试；证明只读行为。
- **实机阶段（A7）：** 在标明固件 hash 与设备身份的真机上抓到可解析网络日志，证明帧时效、断线恢复和 UART 对照；记录脱敏样本与丢失计数。源码/API 或模拟测试不能替代 L3 实测。

## 5. 后续归属

下一步由 **A0** 对“是否纳入网络日志”作明确范围决定；若纳入，A0 先完成 §3 契约并与 A1 确认真实固件日志源。契约冻结后，A1 实现设备侧来源，A7 实现只读采集与验收。A7 缺口记录保持为证据材料，不由本 CR 改写。当前没有网络日志代码修改或设备网络测试。
