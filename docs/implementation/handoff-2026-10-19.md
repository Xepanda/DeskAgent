## 后续工作包与顺序

### P0 / A1：联网内存及音频硬件闭环

1. 保留已绑定身份和网络。只读采集联网空闲、诊断、语音开始/结束阶段的内部/PSRAM free、largest、minimum，以及线程栈余量。找出联网后内部内存消耗，避免盲目缩栈或全局改写 malloc。
2. 使用 `tal_psram_malloc`、`THREAD_CFG_T.psram_mode=1` 等已有设施；需指定 CPU 核的 AFE 使用 IDF Caps 任务接口。DMA、ISR 和必须内部 RAM 的对象不迁移。
3. 复用 SDK 成熟音频输入、输出、KWS/VAD、ASR/LLM/TTS；只完善 Watcher 的 TDD/HAL。核对官方 ES8311/ES7243E 的 I2S slot、通道、共享 data interface、MCLK、PA、增益和静音状态。
4. 特别核对上游 `audio_codec_i2s_cfg_t.keep_slot_config` 与本地 esp_codec_dev 版本差异。官方 BSP 固定双工 TX/BOTH、RX/RIGHT；当前 codec open 可能重新配置 slot，应通过源码和实测裁决，不能盲目增加 gain。
5. 测试窗口要覆盖用户操作，提前告知提示音时间；每次播放短时、低音量、有界。采集 PCM 峰值/RMS/削波计数，不上传原始用户音频。验证真实“你好小智”事件、VAD、云端识别和回复播放。
6. 验收：内部内存余量有测量依据且可承受业务峰值；无分配失败/panic/持续下降；用户确认听音、唤醒和一句真实云端对话，提供对应日志；断网/恢复后再次通过。未达到则不宣布语音完成。

### A1：相机、输入与 STM32（按子任务逐项派发）

- 复用 WatcheRobot-public 固定提交 `e89a5fd3ae9fa9115e5122e252ab90fe5dd0b72b` 的 `watcher_hx_ptl`、`watcher_hx_control`、`hx_media_protocol`、`hx_ptl_protocol`，对接既有 SDK 媒体链路，不另造模拟流。
- 官方是 PTL Himax 运行时；不要混用原 Seeed SSCMA 命令，也不刷 Himax。SPI2 4/5/6、CS21、expander SYNC6；控制 UART1 TX17/RX18，均需对照实际硬件和源码再使用。
- 上游 IDF 6.0.2 使用的 `SPI_TRANS_DMA_USE_PSRAM` 在本地 IDF 5.4 不存在；评估最小 DMA bounce/接口适配，保留 CS、包完整性、CRC、帧时效和所有权。复用现有 I2C0/PCA9535，避免第二个 bus owner。
- 先真实鲜活 JPEG，接入既有局域网查看，再按产品需要验证媒体通道。不得以静态图、注入帧、历史缓存或单帧冒充完整视频流；不自行扩展录像/监控音频。
- 触摸、旋钮和表情状态适配已有硬件接口。
- UI/表情参考用户指定的 [jeremy-prt/bloub](https://github.com/jeremy-prt/bloub)，调研固定提交 `b4bb3c1b5f93c7b87a2e8d620f667c4093d97749`。它是 Vue/TypeScript/SVG 实现，含独立 `src/bot` 形态/眼睛/时间采样引擎及资源导出能力，可参考眨眼、视线、形变、过渡；不能直接把浏览器应用当作 ESP32 驱动。代码 MIT，保留许可；上游明确许可不覆盖其模仿的第三方视觉设计，产品采用自己的形象。先做 412×412 圆屏上的最小可用状态映射，按真实 idle/listening/thinking/speaking/notification/error/offline 事件驱动，优先复用既有渲染链或受控资源导出，不强制引入新 UI 框架。量测 PSRAM/内部 DMA 缓冲、CPU、帧耗时，确认动画不阻塞音频/网络。当前只记录为后续任务，尚未移植。
- STM32 先核对物理 UART 与官方协议，完成只读握手再发受控动作；COBS 是 A5/5A 帧外层，附 0x00，不能二选一。验收真实 ACK、限幅、停止、断链安全，未经授权不刷 STM32。
